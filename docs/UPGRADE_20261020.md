# Upgrade checklist

1. Preserve a tested database and persistent-volume backup outside the source tree and build context. Record your current image and configuration; do not publish backup contents.
2. Build the reviewed commit with `./scripts/build-image.sh` and use the existing Compose startup path with `--no-build`. Host npm/development dependencies are unnecessary. The default runtime remains small; documents tools are opt-in.
3. Startup applies additive migrations for immutable HTML presentation versions, opportunity images/background feedback and optional judgment records. Existing attachments remain reader documents and retain file IDs and share settings. User state and credentials are never part of an upgrade package.
4. Check username/password login, one synthetic project, queued work, existing reader attachments, interactive artifact controls and explicit export. Enable judgments only if desired. Check timezone previews and use a synthetic one-time schedule. Verify configured voice/memory providers separately; empty settings remain unavailable.
5. Retain a compatible old image and backup until acceptance. Stop new work before rollback; restoring an old application does not automatically restore the database. Rehearse restoration on a copy without touching live data.

The dependency manifests/locks, runtime/docs profiles, Compose volumes and environment keys did not change in this feature update. `.env.example` remains authoritative for optional configuration. No default model choice, provider endpoint, production path or account binding is imported by these features. [Presentation protocol](WEB_PRESENTATIONS.md), [judgments](JUDGMENT_BOOK.md), [schedules](PROJECT_RECURRING_TASKS.md), [feedback](OPPORTUNITY_CARDS.md) and [routing retries](UPSTREAM_RETRY.md) describe behavior and limitations.

Contributor tests on Linux require `acl` (`setfacl`) to exercise tenant upload permissions. The Docker test stage and CI install this test tool explicitly. The runtime already includes it; the default runtime packages and application dependencies are unchanged.
